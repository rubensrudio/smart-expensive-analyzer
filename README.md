# Smart Expense Analyzer

Backend for importing financial statements in CSV format, normalizing and
categorizing transactions, and providing expense analytics through a REST API.

> **Warning:** this is a single-user demo project **without authentication**.
> The API must not be exposed to the internet or to a shared network. See
> [Security and limitations](#security-and-limitations).

## Features

- synchronous import of CSV files, with per-row validation and deduplication;
- automatic categorization based on configurable rules;
- paginated querying of expenses and income;
- totals, mean, median, histogram, and distribution by category and
  merchant;
- monthly expense series, split by currency;
- detection of potential anomalies using the IQR method;
- OpenAPI documentation generated by FastAPI;
- reproducible environment with Docker Compose and automated tests in CI.

## Tech stack

- Python 3.12;
- FastAPI and Pydantic v2;
- SQLAlchemy 2 and Alembic;
- PostgreSQL 16;
- pandas and NumPy;
- pytest, Ruff, and mypy;
- Docker Compose and GitHub Actions.

## Security and limitations

The first version is single-user and **has no authentication** (decision
LAC-01). Any client that can reach the API port can read, create, and modify
financial data. For this reason, the API must not be exposed to the internet
or bound to a public network interface. Docker Compose publishes the API only
on `127.0.0.1:8000` and does not publish the PostgreSQL port.

Known risks, accepted for this version and tracked as follow-ups:

- **Local-network CSRF (FUP-03):** a malicious page opened in a browser on
  the same machine can send requests to `http://localhost:8000`. Binding to
  loopback does not prevent this scenario.
- **Unbounded upload before parsing (FUP-03):** the endpoint reads at most
  `MAX_UPLOAD_MB` + 1 byte and returns 413 above the limit, but Starlette
  writes the entire multipart body to a temporary file before that. A very
  large upload consumes temporary disk space before it is rejected.
- **Cost of `/analytics/monthly` with an extreme date range (FUP-05, high
  severity):** the series has one item per month in the period, with no
  limit. A range such as `0001-01-01` to `9999-12-31` produces about 120,000
  months per currency, with a high memory and time cost, and may exhaust the
  process memory.

Currency conversion, a graphical interface, banking/Open Finance integration,
and production deployment are out of the initial scope.

## Running with Docker

Prerequisites: Docker and Docker Compose. From a clean clone:

```bash
cp .env.example .env
docker compose up -d --build
```

Alembic migrations are applied automatically before the API starts. After
that, the following are available:

- interactive documentation: <http://localhost:8000/docs>;
- OpenAPI specification: <http://localhost:8000/openapi.json>;
- health check: <http://localhost:8000/health>.

To shut down the environment:

```bash
docker compose down
```

## Environment variables

The `.env.example` file contains local development values. Copy it to `.env`
and change the password outside the local environment.

| Variable | Required | Default | Description |
|---|---:|---|---|
| `DATABASE_URL` | yes | — | PostgreSQL connection URL for the API |
| `DEFAULT_CURRENCY` | no | `BRL` | ISO 4217 currency used when the CSV does not specify one |
| `MAX_UPLOAD_MB` | no | `10` | maximum size of each imported file |
| `ANOMALY_IQR_K` | no | `1.5` | IQR multiplier for anomaly detection |
| `ANOMALY_MIN_SAMPLE` | no | `8` | minimum sample size per category and currency |
| `LOG_LEVEL` | no | `INFO` | application logging level |
| `POSTGRES_USER` | yes in Compose | — | local PostgreSQL user |
| `POSTGRES_PASSWORD` | yes in Compose | — | local PostgreSQL password |
| `POSTGRES_DB` | yes in Compose | — | database created by the local PostgreSQL |

Never commit the `.env` file or real credentials.

## CSV format

The file must use UTF-8, a comma as the field separator, and a period as the
decimal separator. The header accepts these columns:

| Column | Required | Format |
|---|---:|---|
| `date` | yes | date in `YYYY-MM-DD` format |
| `description` | yes | non-empty description |
| `amount` | yes | decimal; negative for expenses and positive for income |
| `merchant` | no | merchant; falls back to the description when empty |
| `currency` | no | ISO 4217 code; falls back to `DEFAULT_CURRENCY` when empty |

Example:

```csv
date,description,amount,merchant,currency
2026-01-05,Supermercado,-152.40,Mercado Central,BRL
2026-01-10,Salario,5000.00,Empresa Exemplo,BRL
2026-01-12,Transporte por aplicativo,-24.90,Mobilidade,BRL
```

Zero amounts are invalid. Invalid rows are rejected individually, while the
remaining rows are still imported.

## API

| Method | Route | Purpose |
|---|---|---|
| `POST` | `/imports` | import a CSV |
| `GET` | `/transactions` | list and filter transactions |
| `GET` | `/transactions/{id}` | retrieve a transaction |
| `POST` | `/transactions/recategorize` | reapply the existing rules |
| `POST`, `GET` | `/categories` | create and list categories |
| CRUD | `/categorization-rules` | manage categorization rules |
| `GET` | `/analytics/summary` | get the statistical summary |
| `GET` | `/analytics/categories` | get the distribution by category |
| `GET` | `/analytics/monthly` | get the monthly series |
| `GET` | `/anomalies` | list potential anomalies |

## Local development

Requires Python 3.12. Set up the environment with:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev]"
```

To check the project:

```bash
ruff check . --output-format=concise
mypy app
pytest -q
```

pytest uses the root `pytest.ini` (`pythonpath = .`, `--import-mode=importlib`)
and writes the JUnit report to `reports/junit.xml`.

Integration tests use a real PostgreSQL instance through Testcontainers and
require Docker to be running. With colima, you may need to point to the
socket:

```bash
TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE=/var/run/docker.sock pytest -q
```

If the `TEST_DATABASE_URL` variable is set, the tests use that database
instead of starting a container. CI (GitHub Actions, `.github/workflows/ci.yml`)
runs `ruff`, `mypy`, and `pytest` on every push and pull request, with a
`postgres:16-alpine` service, and also validates the API image build.

## Architecture

The project follows Clean Architecture, with dependencies pointing toward the
domain:

```text
app/
├── domain/                 # entities, pure rules, and ports
├── application/services/   # use cases
├── infrastructure/         # database and CSV reading
├── api/                    # routes, schemas, and error handling
└── main.py                 # FastAPI application composition
```

Persistence uses the Repository Pattern and Unit of Work. Configuration comes
from environment variables, and migrations are managed by Alembic.
